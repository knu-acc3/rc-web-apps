# Аудит безопасности

Дата: 1 октября 2026. Проверялся весь код сайта (`app/`, `src/`, `public/sw.js`, `proxy.ts`, `next.config.ts`) и зависимости.

## Как устроен сайт с точки зрения безопасности

- Все инструменты работают в браузере посетителя. Сервер только отдаёт статические страницы: нет базы данных, форм, загрузки файлов, учётных записей и API, которые можно атаковать.
- Content Security Policy запрещает страницам обращаться к другим сайтам (`connect-src`, `img-src`, `form-action` — только свой домен). Даже если бы в странице выполнился чужой скрипт, он не смог бы отправить файлы или текст наружу.
- Тяжёлая и потенциально опасная работа (регулярные выражения, сравнение текстов, PDF, архивы, хеши) идёт в Web Worker: зависание или ошибка не роняет страницу.

## Проверено — в порядке

- **Вставка HTML.** `dangerouslySetInnerHTML` используется в 5 местах: статические встроенные скрипты (тема, проверка старого браузера, регистрация service worker), JSON-LD (символ `<` экранируется, выйти из `<script>` нельзя) и превью Markdown (HTML чистится DOMPurify, ссылки получают `rel="noopener noreferrer"`). Прямых `innerHTML`, `document.write`, `insertAdjacentHTML` нет.
- **Ссылки из пользовательских данных.** Сканер QR делает кликабельными только адреса `http:` и `https:` (не `javascript:`), с `rel="noopener noreferrer nofollow"`. Ссылок `target="_blank"` без `noopener` нет.
- **Перенаправления.** `proxy.ts` перенаправляет только на пути своего сайта (меняется `pathname`, домен — никогда): открытого редиректа нет. Неизвестные адреса получают 404 без рендеринга страницы — их нельзя использовать, чтобы забить кэш.
- **ReDoS.** Проверка регулярных выражений идёт в воркере с таймаутом 1,5 с; поиск и замена, сравнение текстов — тоже в воркерах.
- **Zip Slip.** При распаковке в папку сегменты `.` и `..` из путей выбрасываются — файл не может выйти за пределы выбранной папки.
- **Случайность.** Пароли, жребий, кубики, UUID используют `crypto.getRandomValues`; `Math.random` для этого не применяется.
- **Service worker** обрабатывает только GET-запросы к своему домену и хранит только файлы сайта; введённые данные и открытые файлы не кэшируются.
- **OG-картинки** генерируются при сборке по фиксированному списку разделов (`dynamicParams = false`).
- **Заголовки:** HSTS, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` и `frame-ancestors 'none'` (сайт нельзя встроить в чужую страницу — защита от кликджекинга), `Cross-Origin-Opener-Policy: same-origin`, `Referrer-Policy: strict-origin-when-cross-origin`.
- **Зависимости:** `npm audit` — 0 уязвимостей. Обновлены патч-версии `next` 16.3.8, `eslint-config-next` 16.3.8, `postcss-custom-properties` 15.0.3.

## Осознанно оставлено

- **`script-src 'unsafe-inline'`.** Next.js встраивает в статические страницы небольшие скрипты загрузки; nonce для статических страниц невозможен (он должен меняться на каждый запрос). Риск закрыт тем, что на сервере нет пользовательского контента, React экранирует вывод, а HTML из Markdown чистится DOMPurify.
- **HSTS без `includeSubDomains` и `preload`.** Добавить, когда будет точно известно, что все поддомены работают по HTTPS: отменить preload почти невозможно.
- **Данные в `localStorage`.** Заметки, счётчики, табло и настройки хранятся открытым текстом на устройстве пользователя — так задумано (работа без аккаунта и без сервера). В плане — кнопка «Удалить все данные сайта».
- **Мажорные обновления не сделаны:**
  - `ua-parser-js` 2.x — лицензия сменилась на AGPL-3.0, обновлять нельзя; 1.x поддерживается и без уязвимостей.
  - `typescript` 7 (новый компилятор на Go), `eslint` 10, `@types/node` 26 — ждём поддержки в инструментах Next.js; для безопасности не требуются.
