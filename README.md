# RC Web App — онлайн-инструменты, которые работают в браузере

> Документ актуален на 1 октября 2026. Это единственная документация проекта: при изменении структуры, правил,
> команд или деплоя она обновляется в том же коммите (см. «История» в конце). Таблица разделов ниже собирается из кода
> командой `npm run docs`, и тест не даст ей устареть.

## Что это

Сайт инструментов на русском и английском: PDF, фото, видео и аудио, текст, символы и эмодзи, время и таймеры,
калькуляторы, конвертеры, генераторы, инструменты для разработчиков и SEO, тесты устройств.

- **Всё работает в браузере.** Файлы и введённые данные не уходят на сервер: серверных API нет, а политика безопасности
  (CSP) запрещает страницам отправлять данные на другие сайты.
- **Каждый инструмент и каждый полезный вариант — отдельная страница** («Таймер на 5 минут», «Километры в мили»,
  эмодзи, город). Страницы собираются заранее (static generation), поэтому быстро открываются и индексируются.
- **Телефоны от iPhone 4 (320×480) до 8K-телевизоров**, старые iPhone (Safari 14) и работа без интернета для уже
  открытых страниц.

Стек: Next.js 16 (App Router, Turbopack), React 19, Tailwind CSS 4, TypeScript (strict), Vitest, Playwright.
Название сайта, домен, автор (rc-web.kz, указан в подвале каждой страницы) и коды вебмастеров — только в
`src/config/brand.ts`; знак логотипа — `src/site/logo-mark.ts` (из него же `public/favicon.svg`).

## Структура

```
src/
  app/          маршруты Next.js (тонкий слой): страницы, sitemap, OG-картинки (и их шрифты), поиск, 404
  proxy.ts      каждый запрос: известная страница → показать, старый адрес → 301, неизвестный → 404
  tools/        ВСЕ ИНСТРУМЕНТЫ: tools/<категория>/<раздел>/ (таблица ниже)
  site/         оболочка сайта: шапка, подвал, страница инструмента, блоки, поиск, SEO, sitemap;
                site/about — страницы «О сайте» и «Конфиденциальность»
  ui/           общие компоненты Material 3: кнопки, поля, списки, числа (− +), ползунки, сегменты, ленты чипов,
                карточки, загрузка файлов, полноэкранный режим
  lib/          общие функции без интерфейса: буфер обмена, сохранение настроек, ссылки с настройками, шкалы ползунков
  registry/     реестр разделов: типы страниц, категории, семейства инструментов, сборка страниц
  i18n/         языки, форматирование чисел и дат, словарь интерфейса
  config/       бренд (название, домен) и карта старых адресов
public/         иконки, шрифты, service worker (офлайн); public/vendor создаётся при сборке
scripts/        шаги сборки, генераторы данных (scripts/data), IndexNow, правило сборок Vercel
tests/unit/     юнит-тесты, разложены по тем же категориям, что и src/tools; tests/e2e — Playwright
```

### Папка раздела

```
src/tools/<категория>/
  shared/               то, чем пользуются несколько разделов категории (например, редактор кода у dev/)
  <раздел>/
    section.ts          страницы раздела: инструменты, варианты, тексты, SEO
    components.ts       id компонента → ленивая загрузка (только import())
    Название.tsx        компоненты инструментов; у больших разделов — по папке на инструмент (calc/, finance/)
    lib/                логика, движки, воркеры — без React, покрыты тестами
    content/            тексты страниц: заголовки, инструкции, FAQ, варианты
    data/               таблицы и JSON (сгенерированные — из scripts/data)
    ui/                 виджеты, общие для инструментов раздела
```

Категория — это пункт меню сайта, раздел — группа инструментов одной темы. Папка категории называется так же, как её
id в `src/registry/categories.ts`, папка раздела — как id раздела.

## Как получается страница

1. `src/app/[locale]/…/page.tsx` вызывает `resolvePage(locale, путь)` из `src/registry`.
2. Реестр находит раздел, которому принадлежит адрес, и вызывает его `resolve()`. Раздел возвращает модель страницы
   (`PageModel`, `src/registry/types.ts`): title, h1, description, lead (ответ одной строкой), хлебные крошки, инструмент
   с параметрами, блоки с данными, инструкцию, FAQ и связанные инструменты.
3. `src/site/page-view.tsx` рисует страницу, `src/site/seo.tsx` — метаданные, canonical, hreflang и JSON-LD.
4. Сам инструмент — отдельный чанк из `src/tools/tool-components.ts` (генерируется перед сборкой), поэтому страница
   грузит только свой инструмент.

Sitemap (`/sitemap.xml` → `/sitemaps/<раздел>.xml`) и поисковый индекс собираются из тех же разделов. Дата изменения
(`lastmod`) раздела — дата последнего коммита в его папке.

## Как добавить инструмент

1. Выбрать раздел (или создать папку `src/tools/<категория>/<раздел>/` и добавить раздел в `src/tools/index.ts`).
2. Компонент `Название.tsx`: `"use client"`, экспорт по умолчанию, пропсы `{ locale, ...настройки }`, строки в
   `const T = { ru: {…}, en: {…} }`. Логику — в `lib/` с тестом в `tests/unit/<категория>/`.
3. Зарегистрировать в `components.ts` раздела: `"раздел/имя": () => import("./Название")`.
4. Описать страницу (`ToolDef` в `content/` или `section.ts`): slug — английская форма главного запроса
   (`merge-pdf`, `word-counter`), title, h1, description, lead, 3–5 шагов, 3–5 вопросов, связанные инструменты.
5. `npm run verify` и `npm run docs`, если поменялся набор разделов или страниц.

## Правила

**Главные**
- Всё в браузере: никаких серверных API, сторонних скриптов, шрифтов и аналитики в инструментах.
- Никаких фальшивых возможностей: текст описывает только то, что инструмент делает на самом деле.
- Всё на двух языках, правильные склонения (`plural()` из `src/i18n/format.ts`).
- Результат считается сразу, без кнопки «Рассчитать»; страница варианта показывает ответ уже в HTML.
- Тяжёлые библиотеки (pdf-lib, ffmpeg, wasm-кодеки) — только через `await import()` при использовании; тяжёлые
  вычисления — в Web Worker.

**Интерфейс (Material Design 3, но понятный)**
- У инструмента одна точка внимания: главное поле и крупный результат. Один переключатель режима сверху, одно
  главное действие — кнопка `filled`; второстепенные — `tonal`, `outlined`, `text`; иконки панели — `IconButton`.
  Образец подхода — «Жребий» (`src/tools/random/random/DrawLots.tsx`): крупное действие, осязаемый результат, мало текста.
- Списки — `Select` (родной список в поле Material, ширина по тексту, без фиксированных `w-*`); числа — `NumberInput`
  (− и + вместо стрелок браузера); числа с разумным диапазоном (возраст, сумма, %, срок) — `SliderField` /
  `NumSlider`: значение на линии и ползунок под ним, деньги — логарифмическая шкала. 2–5 вариантов — `Segmented`,
  больше — чипы. Ряд, который может не влезть, — `ScrollRow` (затухание краёв и стрелки ‹ ›). Голые `<select>`,
  `type="number"` и `type="range"` запрещает линтер.
- Никакой рамки в рамке: карточки (`Panel`) без рамок, с тенью; карточка внутри карточки сама становится тональной
  подложкой. Поля — с заметной обводкой, кнопки — с заливкой, состоянием при наведении и «рябью» при нажатии.
- Работает от 320×480 до 8K: размеры в `rem`, контейнер до 96rem, на широких экранах ввод и результат рядом,
  длинные строки и формулы переносятся, кнопки на сенсорных экранах 40–48px, поля на телефоне не мельче 16px.
- Иконки вместо слов там, где иконка понятна всем (поиск, меню, копировать, скачать, закрыть); у такой кнопки есть
  `aria-label`. У каждого поля есть подпись.
- Готовые компоненты из `src/ui` и цвета из токенов (`bg-surface`, `bg-accent-container`, `text-fg-2`, `text-accent`…),
  без своих стилей с нуля.
- Настройки, которые должны пережить перезагрузку, — `usePersistentState` из `src/lib/persist.ts`.

**SEO**
- Title и h1 — то, что люди вводят в поиск. Формат title: `<точный запрос> | <второй вариант запроса>`.
- `tests/unit/site/seo-quality.test.ts` проверяет каждую страницу: длину и формат title, уникальность h1, длину
  description, свои данные на каждой странице варианта, отсутствие почти одинаковых страниц.
- Варианты — только с реальным спросом и своими данными; тонких страниц, отличающихся одним числом, не делаем.

**Безопасность**
- Строгая CSP, HSTS, запрет встраивания сайта в чужие страницы (`next.config.ts`). `script-src 'unsafe-inline'`
  оставлен сознательно: Next.js встраивает загрузочные скрипты, а nonce для статических страниц невозможен.
- HTML из пользовательского ввода не вставляется; превью Markdown чистится DOMPurify; ссылки из данных — только
  `http:`/`https:` с `rel="noopener noreferrer"`.
- Случайные числа — только `crypto.getRandomValues`; регулярные выражения пользователя — в воркере с тайм-аутом;
  распаковка ZIP ограничена 2 ГБ на файл.
- Заметки, счётчики и настройки хранятся только на устройстве; на странице «Конфиденциальность» их можно удалить.
- Открытые фото, пока человек переходит между фото-инструментами, лежат только в этом браузере (IndexedDB
  `rc-workspace`, `src/tools/files/shared/workspace.ts`): одна вкладка, до 6 часов, ограничение по числу и объёму;
  удаляются кнопкой «Начать заново» и «Удалить все данные сайта».

**Старые устройства**
- JS для браузера — уровня Safari 14, без lookbehind в регулярных выражениях (`src/lib/lookbehind.ts`):
  `scripts/postbuild.mjs` проверяет это и создаёт `public/legacy.css` для iOS ниже 15.4.
- Service worker (`public/sw.js`) хранит только файлы сайта; при изменении правил кэша поднимается `VERSION`.
  Скрипты Web Worker он не перехватывает: ответ из кэша теряет `#params` в адресе воркера Turbopack, и PDF-, фото- и
  видеоинструменты перестают работать (проверяет e2e-тест).

## Команды

```bash
npm ci              # установка
npm run dev         # сервер разработки
npm run build       # сборка (перед ней — карта компонентов и копирование wasm/шрифтов в public/vendor)
npm start           # запуск собранного сайта
npm run verify      # линтер, типы, мёртвый код (knip), юнит-тесты, сборка
npm run test:e2e    # Playwright: страницы, 320px, доступность, PDF под service worker (нужна сборка;
                    # PW_CHROMIUM=<путь к chrome> — взять уже установленный Chromium)
npm run docs        # обновить таблицу разделов в этом файле
npm run indexnow -- --since=<коммит прошлого деплоя>   # сообщить Яндексу и Bing об изменённых страницах
```

## Деплой (Vercel, бесплатный план)

- Сайт собирается на Vercel **только из ветки `main`**: другие ветки не деплоятся (`vercel.json`).
- Даже в `main` сборка пропускается, если поменялись только документация, тесты или настройки CI
  (`scripts/vercel-ignore-build.sh`).
- Порядок работы: изменения копятся в рабочей ветке, на каждый push GitHub Actions бесплатно запускает все проверки и
  сборку; в `main` уходит готовый результат одним слиянием — это одна сборка на Vercel.
- После деплоя — `npm run indexnow -- --since=<коммит прошлого деплоя>`.
